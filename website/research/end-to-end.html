Research · Nov 2026 · Integration

The whole navigator, run once on a site it never saw.

We ran the frozen models and the rover brain together, in the order the code wires them, on lunar site DM1. All 65 integration checks passed. This is an integration test on one site and date, not a benchmark.

What we tested

The question was whether the parts work together: does each hand-off carry the right shape, unit and value range, and does the rover read what we say it reads. Site DM1 is not among the training sites, the validation site or the held-out test sites of any model. The three network checkpoints are the frozen ones from the overnight run: their SHA-256 checksums equal the frozen record. Nothing was tuned or chosen from this test. The date, 2027-06-01, is the default of the rover code; DM1 is the first of the six fresh sites by name.

Final run with rover brain v3.1: 432.41 s on a Mac mini (Apple silicon, CPU only, 6 threads). The same run on a MacBook a few minutes earlier took 338.42 s with the same 65 checks and identical rover rates. The checks: 33 on the rover, 8 on the rover world, 6 on the hazard map, 6 on the light, 5 on the terrain tile, 4 on the terrain side branch, 3 on checkpoint identity.

What is really wired

  • Hazard U-Net → rover: wired. The rover world loads the hazard U-Net's probability map and uses it for route cost and score. It is the only network the rover reads. The map equals the one the rover v3 evaluation used on the Mac mini (largest difference 0.0; no pixel changed side at 0.5).
  • Light network → rover: not wired. The rover's light is the exact physics ray-cast. The light network ran on the same grid and produces the same kind of array, so it could be connected, but no code passes it on. As a sanity number on this one site, its skyline differed from the exact ray-cast by 0.27° on average, against 0.35° for the coarse ray-cast backup.
  • Terrain output → anything: not wired. The diffusion network's generated terrain is a side output, labelled "GENERATED — NOT OBSERVED". Hazard, light and rover all read the LOLA tile.
  • Rover ↔ lander pilot: not wired. The lander pilot is a separate package. The rover's lander sits at the centre of its world, not at a landing point chosen by the pilot.

No hand-off was found broken and no stage runs on a stub. The models run together; they do not form one connected pipeline beyond the hazard map.

The rover on DM1

Strict rule: a rover whose battery is empty at any hour, anywhere, is lost; it returned only if it completed the trip without ever being empty. On 2027-06-01, v3.1 returned 232 of 512 rovers, kept 19 alive without a completed trip and lost 261 (51.0%). v3 lost 58.6% and the naive planner 70.3%. All four dates below were run in the same test; every rate equals the reported rover v3.1 evaluation exactly.

Making it faster without changing the answer

On an earlier run (rover v3, MacBook CPU, 2 threads, machine shared with other jobs) two stages on the rover's path were slow. Both were sped up in a separate copy of the code; the frozen run was not touched.

stagebeforeafter
Rover evaluation, 4 DM1 worlds168.0 s69.8 s
Hazard map for the rover130.3 s61.9 s
  • Rover evaluation. The light sampler read a whole 64 × 64 slice per rover to get one value; it now reads the 4 neighbouring cells. Sampled values differ by at most 1.19e-07, and every rover has the same outcome and the same score in all 4 worlds.
  • Hazard map. The U-Net ran on all 16 windows of the tile; the rover needs the central 4. The rover-world crop is identical bit for bit.
  • The rover's path with both speed-ups passed 55 checks, 0 failed, in 266.97 s. The first run of the whole chain (rover v3) had passed 56 checks in 1,293.9 s on the same shared MacBook. Running the hazard U-Net on the Apple GPU was not tried; the GPU was busy with another job.

Limits

  • One site and one main date. It shows that the parts run together without error; it is not a score for how well they generalise.
  • Everything is simulation on NASA LOLA terrain. Shadow-edge targets are dark and cold, not confirmed ice.
  • Stage times depend on the machine and on what else it is running, so they vary between runs.

Method & data

One script ran every stage in order and wrote a result file with each array's shape, unit, value range and count of non-finite values, the outcome of every check, the time and peak memory per stage, and the rover rates for every method and date. A second script drew the figure from that file.
